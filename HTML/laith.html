L.Λ.I.T.H.49

Logical Assistant for Intelligent Task Handling

My personal voice assistant. Wakes on "Hey 49", transcribes the command, runs it, and speaks the response with an animated speech-bubble overlay. Two builds: a cloud one (Azure + Gemini) and a fully local one (faster-whisper + Kokoro + LM Studio + searxng). Same dispatcher, same integrations, same C# event loop driving both.

What it does

[ 13 commands · 4 domains ]

L.A.I.T.H.49 listens for the wake word, then routes whatever you say through a command dispatcher. Recognized verbs control devices and apps directly; anything else falls through to Gemini for a conversational answer (with Google Search grounding for current events).

Voice & AI [ 03 ]

"Hey 49" Custom on-device wake word
anything else Falls through to Gemini for Q&A
greetings + replies Time-of-day-aware, randomized greetings

Smart Home [ 03 ]

"turn on/off the LED / bedroom lights" Control lights over local network
"open/close the door" Arduino-driven door actuator
"turn on the PlayStation" PS5 power + game launching

Information [ 04 ]

"what time / day is it?" Local clock and date readout

Two builds

[ CLOUD + LOCAL ]

Same dispatcher, same integrations, two ways to handle speech and AI. The main branch leans on Azure and Gemini for the best voices and the smartest LLM. The local branch swaps them for open-source equivalents that run on the same machine, so no internet and no API keys.

main

Cloud build

Best quality. Needs internet + paid API keys.

  • STT: Azure SpeechRecognizer
  • TTS: Azure neural voices
  • LLM: Gemini 2.5 Flash with google_search grounding
local

Local build

Runs offline. No API keys, no rate limits, no telemetry.

  • STT: faster-whisper
  • TTS: Kokoro
  • LLM: LM Studio serving llama-3.2-3b-instruct
  • Search: searxng (replaces google_search grounding)

Architecture

[ REQUEST FLOW ]

A single C# event loop drives the whole thing. Speech in, dispatch on intent, fall through to the LLM if nothing matches, then speak the result back. Python services (bubble UI, SMS, PS5 control) sit alongside via a live pythonnet bridge, sharing the same process, just behind Py.GIL().

01
WAKE Azure on-device KeywordRecognizer matches "Hey 49" Reused across cycles so WASAPI doesn't re-init the mic every loop. The keyword catches first-try instead of after a retry.
02
GREET Time-of-day greeting, spoken through whichever TTS the build is wired to. Cloud: Azure neural voice (en-US-AndrewMultilingualNeural) with its TLS connection pre-opened at startup so the first phoneme isn't clipped. Local: Kokoro running on-device.
03
LISTEN Transcribe the command. Cloud: Azure SpeechRecognizer.RecognizeOnceAsync(), with an optional custom endpoint via SPEECH_ENDPOINT_ID and contact names pushed into the phrase list for accuracy. Local: faster-whisper running on-device.
04
DISPATCH Intent matched against a chain of lower.Contains(...) rules Lights, door, PS5, weather, prayer times, contacts, IDE, shutdown. Each handler is a separate service class.
05
FALLBACK No match → hand it to the LLM. Cloud: Gemini 2.5 Flash with google_search grounding so current-events questions still work. Local: LM Studio serving llama-3.2-3b-instruct, with searxng providing the search results. Same system prompt across both, enforcing a terse voice-friendly tone.
06
SPEAK TTS + pygame bubble run in parallel; can be interrupted A side-channel ListenForInterruptionAsync() runs alongside every Say(). Hearing "Hey 49" mid-response cancels the synthesizer, retracts the bubble, and skips the next greeting.

Why it feels fast

[ optimizations ]

Voice UX lives and dies on latency. A few small choices keep the round-trip from wake word to first audio under the "is it broken?" threshold.

REUSE

Keyword recognizer lives across cycles

Building a new KeywordRecognizer per cycle re-opens WASAPI audio capture that takes ~9 seconds on some machines. Constructing it once and reusing it every loop iteration kills the dead air.

PARALLEL

Speech bubble + TTS run side-by-side

Say() fires TTS on the threadpool and immediately calls SpeechBubble(), which blocks until shared state flips. The synth's completion callback flips the state, retracting the bubble exactly when audio ends. Awaiting TTS first would leave the bubble stuck open.

ISOLATE

Two SpeechConfig instances, never shared

The recognition config can target a custom Azure STT endpoint via EndpointId. The synth config never gets that property, applying it to the synthesizer causes silent TTS failures with no error.

HOT

Pygame display dies, fonts stay warm

The bubble calls pygame.display.quit() after each speech, not pygame.quit(). Fonts stay loaded in module state, so the next bubble re-inits in milliseconds instead of seconds. Hiding the SDL window instead hangs set_mode for ~20s.

DPI

Process-wide DPI awareness, set first

SetProcessDpiAwareness(2) runs at the very top of SpeechBubble.py, before import pygame. If pyautogui later flips DPI mode mid-process, pygame's window shrinks to a quarter of its size

SSML

IPA phonemes for prayer names

An English neural voice mangles "Fajr," "Maghrib," "Isha." Wrapping the names in SSML <phoneme> tags with IPA pronunciations makes the synthesizer say them correctly. (Cloud-only; the local Kokoro path uses a different pronunciation tweak.)

SWAP

STT, TTS, and LLM hide behind shared interfaces

Each external service sits behind a small abstraction so the cloud and local builds share the same dispatcher and event loop. Swapping Azure for faster-whisper, or Gemini for an LM Studio model, is a constructor change. Nothing in Program.cs knows whether you're online.

Code, briefly

[ Program.cs / main loop ]

The whole dispatch is a flat if/else chain. Boring on purpose: fast to read, easy to add the next command without standing up a router.

Program.cs C# 
while (true) {
    await speechManager.KeywordRecognizer();          // wait for "Hey 49"
    var greeting = PickGreeting(DateTime.Now.Hour);
    await speechManager.Say("Hey 49", greeting);

    var result = await speechRecognizer.RecognizeOnceAsync();
    string lower = result.Text?.ToLower() ?? "";

    if (lower.Contains("turn on") && lower.Contains("light"))
        await lightControl.TurnOnLights(...);
    else if (lower.Contains("door"))
        await arduino.ArduinoCommunication("OPEN");
    else if (lower.Contains("weather"))
        await weather.GetWeatherData();
    // ...11 more handlers...
    else if (result.Reason != ResultReason.NoMatch) {
        var reply = await GeminiService.GenerateGeminiResponse(result.Text);
        await speechManager.Say(result.Text, reply);
    }
}
